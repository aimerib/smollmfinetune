### **R4-2: Narrative Engine - Unified Dataset Pipeline**
Status: **Todo**
Ring: R4
Created: 2025-06-19

#### **Goal**
Create a robust data pipeline that can process, validate, and prepare datasets conforming to the new unified schema, including tools to convert existing character data into this format.

#### **Context**
The Narrative-LLM requires a specific data format that includes session IDs, persona mixes, memory slots, and tagged assistant turns (text vs. action). This task builds the ETL (Extract, Transform, Load) pipeline to handle this new schema. It's the bridge between the data generated by your existing Devkit and the input expected by the new model.

#### **Acceptance Criteria**
- [ ] Pydantic models for the new dataset schema (`Turn`, `DatasetSample`) are defined in `narrative_engine/data_schema.py`.
- [ ] A script `scripts/convert_to_narrative_format.py` is created. It can take a character's directory (with `character_core.json`, `mes_example.txt`, etc.) and convert it into a valid `DatasetSample` JSON object.
- [ ] A `DatasetProcessor` class in `narrative_engine/data_pipeline.py` is implemented with methods to:
    - Validate a batch of samples against the Pydantic schema.
    - Tokenize the text and tag spans for the dual-head loss function (e.g., create a `loss_mask` tensor).
    - Prepare data for a PyTorch `DataLoader`.
- [ ] The processor correctly handles the `persona_mix` and `memory_slots` fields.

#### **TDD Instructions**
1.  **Red (Failing Test - Schema):** In `tests/narrative_engine/test_data_pipeline.py`, write a test `test_schema_validation()` that creates a dictionary matching the example JSON from the proposal and tries to validate it with a `DatasetSample` Pydantic model. It will fail as the model doesn't exist.
2.  **Green (Passing Test - Schema):** Implement the Pydantic models to make the validation test pass. Add a test for an *invalid* schema to ensure it correctly raises a `ValidationError`.
3.  **Red (Failing Test - Conversion):** Create a dummy character folder structure in your test assets. Write a test `test_character_to_narrative_sample()` that calls a (not-yet-existing) conversion function and asserts the output is a valid `DatasetSample` object.
4.  **Green (Passing Test - Conversion):** Implement the conversion script logic to pass the test.
5.  **Red (Failing Test - Tokenization & Masking):** Write a test `test_dataset_processor_output()` that instantiates the `DatasetProcessor`, gives it a valid sample, and asserts that the output dictionary contains correctly shaped `input_ids`, `attention_mask`, and `loss_mask` tensors. The `loss_mask` should correctly identify which tokens belong to the "action" head vs. the "text" head.
6.  **Green (Passing Test - Tokenization & Masking):** Implement the processing logic in `DatasetProcessor` to correctly tokenize and create the loss masks.
