## Goal
Deliver a real-time "Director's View" Streamlit page that visualises world state, agent subtext (R5-2), live actions, and **memory formation dynamics**, turning the platform into an interactive god-view debugging and storytelling console.

## Context
Writers need to observe and steer the emergent simulation. A graphical, auto-refreshing dashboard that surfaces subtext, relationships, actions, and **real-time memory formation** is critical for validating R5 proactive agents and ecology behaviour.



## 3. How? (The Implementation)
This will be a new page in the Streamlit application that reads data asynchronously 
from the `RuntimeStateManager`.

1. **Create the `Director's View` Page:**
   - Add a new page: `app/pages/directors_view.py`.
   - This page will establish a connection to the running `RuntimeStateManager`.

2. **Live World State Map:**
   - The main component of the page will be a visual map of the world.
   - Use a library like `streamlit-agraph` or `plotly` to create a node-graph 
   visualization.
   - Periodically (e.g., every 5 seconds), fetch the latest state from the 
   `RuntimeStateManager` using `get_all_entities()`.
   - Nodes will represent locations and agents. Edges can represent relationships or 
   recent movements.
   - Clicking on an agent node will open a sidebar with their detailed state.

3. **Agent Detail Sidebar:**
   - When an agent is selected, a sidebar (`st.sidebar`) will display:
       - Their full state from the `StateManager` (inventory, status, goals).
       - A live-updating log of their recent actions and subtext. This will involve 
       querying the `StateManager` for the latest subtext logs for this agent (as 
       generated by R5-2).
       - **NEW**: Active emotional momentum state with decay visualization
       - **NEW**: Memory formation history (last 10 memories with importance scores)
       - **NEW**: Current surprise level indicator

4. **Asynchronous Data Fetching:**
   - The page must not block while waiting for updates. Use Streamlit's session state 
   and auto-refresh capabilities (`st.experimental_rerun`) or a more advanced async 
   pattern to keep the view updated without a poor user experience.

## 4. How to Test?

- **UI Tests (`tests/ui/test_directors_view.py`):**
   - Create an `AppTest` for the new page.
   - Mock the `RuntimeStateManager` interface.
   - In the test setup, have the mock `StateManager` return a predefined set of 
   agents and locations.
   - Test that the graph visualizer renders the correct number of nodes.
   - Simulate clicking a node and test that the sidebar appears and displays the 
   correct information from the mock state.
   - Test the auto-refresh mechanism by updating the mock `StateManager`'s data and 
   asserting that the UI reflects the change after a refresh cycle.
