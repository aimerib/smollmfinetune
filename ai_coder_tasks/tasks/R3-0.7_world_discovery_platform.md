## Goal
Create a beautiful world discovery interface where players can browse, filter, and select worlds to play in. This is the "world selection lobby" of the platform runtime experience.

## Context
After authentication, players need to discover and choose from available worlds. This is fundamentally different from the devkit world management - this is about **discovery and selection**, not **creation and editing**. Think Netflix world browser, Steam game library, or Roblox game discovery.

## Acceptance Criteria

### 1. World Discovery Database Layer
- [ ] Extend R3-1 schema with discovery-focused fields:
  - `worlds` table: add `published`, `featured`, `player_count`, `avg_rating`, `tags`, `thumbnail_url`
  - `world_stats` table: `world_id`, `total_sessions`, `avg_session_duration`, `active_characters`
  - `world_ratings` table: `world_id`, `user_id`, `rating`, `review_text`
- [ ] Create `WorldDiscoveryManager` separate from `WorldManager` (discovery vs. creation)

### 2. World Publishing Flow
- [ ] Add "Publish World" button to devkit world management (creators only)
- [ ] Publishing wizard: add description, tags, thumbnail, set visibility
- [ ] World approval system (optional): admin review before public listing  
- [ ] Version control: published worlds are snapshots, creators can update/republish

### 3. Discovery Interface (`/worlds` page)
- [ ] **Hero Section**: Featured/trending worlds with large thumbnails
- [ ] **Browse Grid**: Card-based layout with world thumbnails, titles, ratings, player counts
- [ ] **Filtering**: By genre tags, popularity, recency, rating, player count
- [ ] **Search**: Full-text search across world names, descriptions, creator names
- [ ] **World Details Modal**: Expanded view with screenshots, description, character list, reviews

### 4. World Selection & Session Creation
- [ ] "Enter World" button creates a new play session
- [ ] Session creation flow: choose session name, privacy settings (private/friends/public)
- [ ] Redirect to character selection for that world
- [ ] Session persistence: save player progress, return to active sessions

### 5. Social Features (Basic)
- [ ] World ratings & reviews (1-5 stars + optional text)
- [ ] "Favorite" worlds for quick access
- [ ] Recently played worlds section
- [ ] Creator profiles with their published worlds

## Implementation Notes
### UI/UX Design
- **Mobile-first**: Touch-friendly cards, infinite scroll
- **Performance**: Lazy loading, pagination, image optimization
- **Accessibility**: Proper ARIA labels, keyboard navigation
- **Aesthetic**: Modern game platform look (think Epic Games Store meets Character.ai)

### Database Optimization
- Indexed searches on tags, ratings, player_count
- Cached aggregations for popular/trending calculations
- CDN for world thumbnails and assets

## TDD Instructions
- Write unit tests for `WorldDiscoveryManager` filtering and search logic
- Test world publishing flow with role-based permissions
- UI tests for discovery interface interactions (filtering, search, modal)
- Integration tests for world selection → session creation flow

## Example User Flow
1. **Player logs in** → sees personalized discovery page
2. **Browses worlds** → filters by "Fantasy RPG" tag
3. **Clicks world card** → sees details modal with character roster
4. **Clicks "Enter World"** → creates session, redirects to character selection
5. **Returns later** → sees "Continue Session" for active worlds
