## Goal
Expose personality-alignment and lore-adherence evaluation as a reusable HTTP micro-service so that all training, data-collection and CI jobs hit a single, caching endpoint rather than each script calling GPT-4/Claude independently.

## Context
Several tasks (R1-8 metric, R1-9 UI, R3-9 faucet filters, R4-3.5 eval harness) require LLM-as-judge calls. Centralising them reduces latency, cost and ensures consistent prompts + caching.

## Acceptance Criteria
- [ ] **FastAPI App** in `services/judge_service/main.py` with endpoints `/personality_alignment` and `/lore_adherence` (POST JSON: `{text, target}` → returns `{score}`).
- [ ] **Prompt Templates** identical to R1-8 & R1-9 cards, stored in `services/judge_service/prompts/`.
- [ ] **Cache Layer**: SQLite table keyed by `sha256(text+target)` with expiry; cache hit logged.
- [ ] **Dockerfile** producing <300 MB image; health-check route `/health`.
- [ ] **Helm Chart** stub for future k8s deploy.
- [ ] **Unit Tests** `tests/services/test_judge_service.py` with FastAPI TestClient and cache hit asserts.
- [ ] **CI Integration**: GitHub Action launches service in background when running eval harness tests.
