## Goal
After selecting a world, players choose which characters to load into their play session. This is the "character roster selection" that happens before starting the actual gameplay experience.

## Context
Once a player has selected a world (R3-0.7), they need to choose which characters will be active in their session. This is different from character creation - players are selecting from **published characters** created by others, not building their own. Think party selection in RPGs or choosing which NPCs to interact with.

## Acceptance Criteria

### 1. Character Publishing System
- [ ] Extend R3-1 schema for character discovery:
  - `characters` table: add `published`, `public_visibility`, `download_count`, `rating`
  - `character_sessions` table: `session_id`, `character_id`, `loaded_at`, `interaction_count`
  - `character_ratings` table: `character_id`, `user_id`, `rating`, `review_text`
- [ ] Character publishing flow for creators: test → publish → review cycle

### 2. Session Management
- [ ] `PlaySession` model: `id`, `user_id`, `world_id`, `name`, `created_at`, `last_active`, `status`
- [ ] Session states: `setup`, `active`, `paused`, `completed`
- [ ] `SessionManager` class to handle session lifecycle and character loading
- [ ] Auto-save session state every 5 minutes during active play

### 3. Character Selection Interface (`/session/{id}/characters`)
- [ ] **World Context**: Display selected world info, lore summary, setting details
- [ ] **Available Characters**: Grid of published characters in this world with:
  - Character portrait, name, personality summary
  - Creator credit, rating, download count
  - "Test Chat" preview button for quick interaction sample
- [ ] **Character Filtering**: By personality traits, character types, popularity, creator
- [ ] **Multi-Select**: Load multiple characters into the session (1-8 character limit)

### 4. Character Loading & Runtime Packet Resolution
- [ ] Integration with R2-1 export system: load runtime packets for selected characters
- [ ] Handle different character sources:
  - **Trained adapters**: Full LoRA/DoRA models with custom training
  - **Base characters**: Use world's base model with personality prompting
  - **Mixed sessions**: Some trained, some base characters
- [ ] Character conflict resolution: handle duplicate names, incompatible personalities

### 5. Session Launch Preparation  
- [ ] **Pre-flight Check**: Verify all selected characters can load properly
- [ ] **Session Settings**: Choose interaction mode (group chat, 1-on-1 switching, narrative mode)
- [ ] **Quick Start**: Auto-select popular character combinations with one click
- [ ] **Launch Session** → redirect to platform runtime interface (R3-1.0)

## Implementation Notes
### Character Discovery UX
- **Preview Mode**: Quick 2-3 message chat samples to test personality
- **Compatibility Hints**: Show which characters work well together
- **Smart Suggestions**: "Players who chose X also liked Y"  
- **Character Sheets**: Detailed personality breakdown, sample conversations

### Performance Considerations
- **Lazy Loading**: Only load character data when displayed
- **Runtime Packet Caching**: Cache frequently used character packets
- **Session Persistence**: Save character selections across browser sessions
- **Concurrent Loading**: Load multiple character adapters in parallel

## Example User Flow
1. **Player selects world** → creates session "My Fantasy Adventure"
2. **Character selection loads** → sees 15 available characters in this fantasy world
3. **Filters by "Friendly"** → narrows to 8 characters with agreeable personalities  
4. **Previews 3 characters** → quick test chats to see personality fit
5. **Selects 2 characters** → "Wise Wizard" and "Cheerful Bard"
6. **Clicks "Launch Session"** → loads runtime packets, redirects to gameplay
