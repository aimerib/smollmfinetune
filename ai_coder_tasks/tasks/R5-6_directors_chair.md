## Goal
Create the "Director's Chair," a radically simplified creator workflow that fuses character interaction, testing, and fine-tuning into a single, fluid conversational interface.

## Context
Inspired by Steve Jobs' obsession with seamless user experiences, this feature eliminates the cognitive overhead of separate "creation," "training," and "testing" pages. The creator simply talks to their character and corrects them in-place. This intuitive act becomes the entire training interface, powered by an "invisible" DPO pipeline that fine-tunes the character in near-real-time.

## Acceptance Criteria
- [ ] New UI: Director's Mode:
  - [ ] A new page, `pages/director_mode.py`, provides a clean, elegant chat interface.
  - [ ] Each message generated by the assistant is editable by the creator.
- [ ] Invisible DPO Workflow:
  - [ ] When a creator edits an assistant's response, the `on_change` callback triggers a backend function, `handle_live_correction`.
  - [ ] `handle_live_correction` receives the context, the original (rejected) response, and the new (chosen) response.
  - [ ] It formats this into a standard preference pair and adds it to a high-priority DPO queue for that specific character's adapter.
- [ ] Real-Time Training Worker (Research-Scale MLOps):
  - [ ] A simple Redis queue for preference pairs with character-specific channels
  - [ ] A lightweight worker process that monitors the DPO queue (can be simple Python script)
  - [ ] When a micro-batch of preference pairs (e.g., 5-10) is available, it triggers a short DPO run (100-1000 steps) on that character's adapter
  - [ ] Simple file-based checkpoint management with atomic swaps
  - [ ] The updated adapter overwrites the previous version, making improvements visible within ~5-10 minutes
  - [ ] Basic progress tracking and failure handling (retry logic, error alerts)
