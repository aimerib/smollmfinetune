# R3-0.5  Platform Authentication & User Management
Status: **Todo**
Ring: R3
Created: 2025-01-14
---

## Goal
Transform the single-user devkit into a multi-user platform with proper authentication, user accounts, and role-based access control. This enables the "Access website" part of the platform user flow.

## Context
Before players can discover worlds and characters, they need to access the platform. This card establishes the foundation for the platform runtime by adding user authentication, account management, and role separation between creators (who build characters) and players (who interact with them).

## Acceptance Criteria

### 1. Authentication System
- [ ] Implement OAuth2 authentication using FastAPI + JWT tokens
- [ ] Support login via email/password and social providers (Google, Discord)
- [ ] Create `app/utils/auth/` module with `AuthManager` class
- [ ] Add secure password hashing with bcrypt
- [ ] JWT tokens with refresh capability (access: 1hr, refresh: 30 days)

### 2. User Roles & Permissions
- [ ] Define user roles: `admin`, `creator`, `player`
- [ ] **Creators**: Can build worlds, create characters, run training jobs
- [ ] **Players**: Can discover worlds, select characters, start play sessions
- [ ] **Admins**: Full access to all platform features + user management
- [ ] Role-based middleware for protecting routes and UI elements

### 3. User Management UI
- [ ] `/login` and `/register` pages with clean, modern design
- [ ] User profile page with avatar, preferences, subscription status
- [ ] Admin panel for user management (ban, role changes, usage stats)
- [ ] Account settings: change password, manage connected accounts, GDPR controls

### 4. Database Schema
- [ ] Extend R3-1 schema with user tables:
  - `users`: id, email, username, hashed_password, role, created_at, last_login
  - `user_sessions`: id, user_id, jwt_jti, expires_at, device_info
  - `social_accounts`: id, user_id, provider, provider_id, access_token

### 5. Platform Navigation
- [ ] Add authentication state to all pages
- [ ] Role-based sidebar: Creators see devkit tools, Players see discovery tools
- [ ] Smooth transition from anonymous browsing to authenticated experience

## Implementation Notes
- Use FastAPI dependency injection for auth in Streamlit pages
- Session state management for maintaining login across page navigation
- Rate limiting for login attempts (5 attempts per 15 minutes)
- Email verification for new accounts (optional requirement)
