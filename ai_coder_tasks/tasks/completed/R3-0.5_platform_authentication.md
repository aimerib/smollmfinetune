## Goal
Transform the single-user devkit into a multi-user platform with proper authentication, user accounts, and role-based access control. This enables the "Access website" part of the platform user flow.

## Context
Before players can discover worlds and characters, they need to access the platform. This card establishes the foundation for the platform runtime by adding user authentication, account management, and role separation between creators (who build characters) and players (who interact with them).

## Acceptance Criteria

### 1. Authentication System ✅
- [x] Implement OAuth2-style authentication using SQLite + JWT tokens (Streamlit-native approach)
- [x] Support login via email/password (social providers available for future extension)
- [x] Create `app/utils/auth/` module with `AuthManager` class
- [x] Add secure password hashing with bcrypt
- [x] JWT tokens with refresh capability (access: 1hr, refresh: 30 days)

### 2. User Roles & Permissions ✅
- [x] Define user roles: `admin`, `creator`, `player`
- [x] **Creators**: Can build worlds, create characters, run training jobs
- [x] **Players**: Can discover worlds, select characters, start play sessions
- [x] **Admins**: Full access to all platform features + user management
- [x] Role-based middleware for protecting routes and UI elements

### 3. User Management UI ✅
- [x] `/login` and `/register` pages with clean, modern design
- [x] User profile page with avatar, preferences, subscription status
- [x] Admin panel placeholders for user management (full implementation in future cards)
- [x] Account settings: change password, manage connected accounts, GDPR controls (placeholders)

### 4. Database Schema ✅
- [x] Implement lightweight SQLite schema with user tables:
  - `users`: id, email, username, hashed_password, role, created_at, last_login
  - `user_sessions`: id, user_id, jwt_jti, expires_at, device_info
  - `social_accounts`: id, user_id, provider, provider_id, access_token

### 5. Platform Navigation ✅
- [x] Add authentication state to all pages
- [x] Role-based sidebar: Creators see devkit tools, Players see discovery tools
- [x] Smooth transition from anonymous browsing to authenticated experience

## Implementation Notes

✅ **Modern UI Design**: Created beautiful login/register pages with form validation and user-friendly error messages.

✅ **Extensible Architecture**: Built with patterns that can easily evolve into full FastAPI backend when needed.
