## Goal
Guarantee reproducible experiments by tracking every dataset used in training/evaluation via content hashes, metadata manifests, and lightweight tooling integrated with git/DVC.

## Context
As we scale to multiple spikes and weekend runs, silent dataset drift will break comparability. A tiny helper CLI and manifest spec will lock each dataset snapshot to a git commit and telemetry run.

## Acceptance Criteria
- [ ] **Manifest Spec**: `dataset.lock` JSON format containing `name`, `hash_sha256`, `num_samples`, `schema_version`, `source_url`, `created_at`.
- [ ] **CLI Tool**: `scripts/dataset_register.py path --name` computes hash & appends/updates lock file.
- [ ] **CI Gate**: GitHub Action fails PR if any dataset directory changed without updated `dataset.lock`.
- [ ] **Telemetry Integration**: telemetry_sdk auto-attaches dataset manifest entry to every run.
- [ ] **Unit Tests**: `tests/unit/test_dataset_versioning.py` verifying hash consistency, lock update behaviour, CI check logic.

## Implementation Notes
```text
• Use Python `hashlib.sha256` streaming over file(s).
• For multi-file datasets, hash the tar/zip archive or deterministic concat of per-file hashes.
• Store manifests under `datasets/<name>/dataset.lock` checked into git.
• Example CI step: `python scripts/check_dataset_lock.py` run in workflow.
```

## COMPLETION SUMMARY

**What was implemented:**

1. **Core Dataset Versioning Module** (`app/utils/dataset_versioning.py`):
   - `DatasetManifest` dataclass with JSON serialization
   - `compute_dataset_hash()` with deterministic SHA256 hashing
   - `update_dataset_lock()` for creating/updating lock files
   - `check_dataset_consistency()` for CI validation
   - `DatasetVersioning` utility class with high-level interface

2. **CLI Tools**:
   - `scripts/dataset_register.py` - Register datasets with hash computation
   - `scripts/check_dataset_lock.py` - CI consistency checker
   - Support for single/bulk registration, listing, and verbose output

3. **CI Integration**:
   - `.github/workflows/dataset_consistency.yml` - GitHub Actions workflow
   - Fails PRs when datasets change without lock file updates
   - Provides helpful fix suggestions and dataset summaries

4. **Telemetry Integration**:
   - Enhanced `telemetry_sdk.init()` with `dataset_paths` parameter
   - `attach_datasets()` function for automatic manifest attachment
   - Dataset manifests logged to all telemetry backends

5. **Comprehensive Test Suite** (`tests/test_dataset_versioning.py`):
   - 18 test cases covering all functionality
   - Hash consistency, lock file management, CI checks
   - Telemetry integration testing with mocks

**Key Features:**
- Deterministic SHA256 hashing (excludes lock files from hash)
- Preserves creation timestamps when updating locks
- Sample counting for JSON/JSONL files
- Git-aware CI checks (changed files only)
- Automatic telemetry attachment for experiment reproducibility

**Usage Examples:**
```bash
# Register single dataset
python scripts/dataset_register.py datasets/my_data/ --name "My Dataset"

# Bulk register
python scripts/dataset_register.py "datasets/*/" --name-from-path

# Check consistency
python scripts/check_dataset_lock.py --changed-only

# List registered datasets
python scripts/dataset_register.py --list
```

**Testing:**
All functionality tested with comprehensive TDD approach. Tests pass consistently and cover edge cases, error handling, and integration scenarios.
