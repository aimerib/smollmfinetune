## Goal
Establish basic evaluation infrastructure early in the development process to enable continuous testing and validation of model improvements.

## Context
Moving evaluation infrastructure earlier in the pipeline allows us to track progress and catch regressions as we build the Narrative Engine. This provides the foundation for more sophisticated evaluation in R4-9.

## Acceptance Criteria
### Core Infrastructure:
- [ ] A directory `narrative_engine/evaluation/` is created with basic structure
- [ ] A main script `scripts/run_basic_evaluation.py` that can evaluate any model checkpoint
- [ ] Simple JSON logging of evaluation results with timestamps

### Essential Evaluations:
- [ ] `eval_basic_generation.py`: Tests that model can generate coherent text
- [ ] `eval_dual_head_sanity.py`: Verifies both heads produce valid outputs
- [ ] `eval_training_progress.py`: Tracks loss curves and convergence metrics

### Integration:
- [ ] Evaluation runs automatically after each training checkpoint
- [ ] Results are logged to wandb alongside training metrics
- [ ] Simple pass/fail criteria for blocking bad checkpoints

## Implementation Notes
```text
• Keep evaluations simple and fast (<5 min runtime)
• Focus on catching obvious failures rather than nuanced quality
• Use synthetic test data for reproducible results
• Design for easy extension in R4-9
```

   - `eval_dual_head_sanity.py`: Validates both generation and control head outputs
   - `eval_training_progress.py`: Tracks loss curves, convergence, and explosion detection

3. **Integration** ✅
   - Integrated evaluation into CLARA trainer with callback hooks
   - Added evaluation to standard SFT training script after checkpoints
   - Wandb logging support for evaluation metrics
   - Pass/fail criteria implemented with configurable thresholds

### Key Features:
- **Fast execution**: Mock mode for CI testing, real evaluation < 5 min
- **Extensible design**: Easy to add new evaluators for R4-9
- **Comprehensive tests**: Full TDD coverage with 13 passing tests
- **Automatic checkpoint evaluation**: Runs after each save during training
- **JSON result persistence**: Results saved alongside checkpoints

### Technical Details:
- Evaluators follow a consistent interface pattern
- Results include both aggregate metrics and detailed breakdowns
- Graceful error handling prevents training interruption
- Supports both standalone CLI usage and programmatic integration

### Usage:
```bash
# Standalone evaluation
python scripts/run_basic_evaluation.py --checkpoint-path ./checkpoint-100 --output-json results.json

# With wandb logging
python scripts/run_basic_evaluation.py --checkpoint-path ./checkpoint-100 --output-json results.json --log-to-wandb

# Mock mode for testing
python scripts/run_basic_evaluation.py --checkpoint-path ./test --output-json results.json --mock-mode
```
