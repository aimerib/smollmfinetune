# R6-3.1: Architecture Migration - Backend Unification
Status: **Todo**
Ring: R6
Created: 2025-01-20
---

## Goal
Consolidate multiple FastAPI services into a unified backend architecture, eliminating confusion and creating clear service boundaries for the React+FastAPI migration.

## Context
**Migration Freeze Point**: Post R6-3 Advanced Emotion Control

The platform currently has multiple FastAPI services that create confusion:
- `backend/app/main.py` - New platform backend (WIP)
- `app/inference_engine/core.py` - Production inference engine
- `services/judge_service/main.py` - Model evaluation service

This task consolidates these into a clear, unified architecture that supports both creator and player experiences under the Dreamcast model.

## Acceptance Criteria

### Backend Service Consolidation
- [ ] **Unified FastAPI Backend**: Merge `backend/app/main.py` and `app/inference_engine/core.py` into single service
- [ ] **Clear Service Boundaries**: Separate routers for devkit, inference, and evaluation
- [ ] **Shared Core Logic**: All services use `app/utils/` business logic consistently
- [ ] **Database Integration**: Unified database connection and session management
- [ ] **Celery Integration**: Async task processing for training and generation

### API Architecture Design
- [ ] **Devkit API**: Character management, world building, training endpoints
- [ ] **Inference API**: Chat, generation, voice synthesis endpoints  
- [ ] **Evaluation API**: Model evaluation, comparison, metrics endpoints
- [ ] **WebSocket Support**: Real-time updates for training, chat, Director's Chair
- [ ] **Authentication**: Unified auth across all API endpoints

### Service Migration Strategy
- [ ] **Inference Engine Migration**: Move core inference logic to unified backend
- [ ] **Judge Service Integration**: Integrate evaluation endpoints into main backend
- [ ] **Legacy Support**: Maintain backward compatibility during transition
- [ ] **Configuration Management**: Unified config system for all services
- [ ] **Health Checks**: Comprehensive service health monitoring

### Infrastructure Updates
- [ ] **Docker Configuration**: Updated containers for unified backend
- [ ] **Environment Management**: Consolidated environment variables
- [ ] **Logging System**: Unified logging across all services
- [ ] **Error Handling**: Consistent error responses and handling
- [ ] **API Documentation**: OpenAPI/Swagger docs for all endpoints

## Implementation Notes
```text
• Unified Backend Structure:
  - main.py: FastAPI app with all routers
  - routers/devkit.py: Character, world, training endpoints
  - routers/inference.py: Chat, generation, voice endpoints
  - routers/evaluation.py: Model evaluation endpoints
  - routers/websocket.py: Real-time communication
  
• Service Integration:
  - Keep existing `app/utils/` business logic unchanged
  - Create service layer adapters for different use cases
  - Maintain existing database models and migrations
  - Preserve all existing functionality during migration
  
• Migration Strategy:
  - Phase 1: Create unified backend alongside existing services
  - Phase 2: Update React frontend to use unified backend
  - Phase 3: Deprecate old services once migration complete
  - Phase 4: Clean up legacy code and configurations
```
